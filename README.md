# Ольга — косметология

Сайт-витрина на Vue 3, TypeScript и Vite: процедуры и цены в BYN, галерея по категориям, контакты Ольги. У посетителей нет регистрации, личного кабинета или самостоятельной записи. Временный вход «Кабинет Ольги» находится в шапке и в раскрывающемся меню на небольших экранах. Футер удалён; публичная страница заканчивается контактами.

Это демонстрационный прототип: авторизации, серверного API и постоянной базы пока нет. Все карточки, записи, изменения прайса и фото находятся в памяти вкладки и исчезают при обновлении. Напоминания не отправляются. Используйте вымышленные данные.

## Запуск

Node.js 22.18+ или 24+. Тесты используют встроенную поддержку TypeScript в Node.js.

```sh
pnpm install --frozen-lockfile
pnpm dev
```

Альтернатива: `npm ci` и `npm run dev`. Оба lock-файла поддерживаются; используйте один менеджер пакетов в рабочем каталоге. `pnpm-workspace.yaml` включает `nodeLinker: hoisted` для Windows.

## Интерфейс

Публичный сайт — одна страница: знакомство с Ольгой, прайс, галерея «До и после», кабинет, вопросы о первом визите и контакты. Пункты меню прокручивают к разделам без открытия копий страниц и сброса выбранных категорий. Единственный публичный канал связи — Instagram. Пока его адрес не указан, кнопки открывают окно предварительного просмотра обращения. В шапке два пункта — «Прайс» и «Результаты» — и кнопка связи. Адреса `#price-list`, `#work-gallery`, `#contacts` открывают нужный раздел напрямую; работают история браузера, повторные переходы и возврат из кабинета. Активный пункт меню следует за прокруткой. Кабинет и форма ручной записи остаются отдельными экранами.

Прайс всегда показывает все процедуры без отдельного фильтра. В галерее закреплён боковой фильтр с заголовком «Категории» и отметкой выбранной кнопки; на планшете и телефоне он становится выпадающим списком. Подложка выбранной категории плавно перемещается между кнопками. Сетка меняется через последовательное исчезновение и появление; её высота сохраняется до завершения плавного возврата к заголовку. Быстрый повторный выбор отменяет предыдущую прокрутку, ручная прокрутка также прерывает автоматическую. В верхнем меню подсветка плавно перемещается между ссылками и сохраняет выбранный пункт до завершения перехода. На компьютере после прокрутки появляется кнопка «Наверх». На телефоне, когда основная кнопка первого экрана уходит вверх, появляется нижняя панель Instagram с компактной стрелкой наверх; учтена безопасная зона экрана. Фон плавно меняется между персиковой, розовой, лиловой и сливовой палитрами по положению разделов: `ScrollAtmosphere.vue` использует `requestAnimationFrame`, пассивный обработчик прокрутки и `ResizeObserver`, без библиотеки анимаций. При `prefers-reduced-motion: reduce` фон статичен, а переходы и прокрутка мгновенные.

Публичная часть и все формы кабинета используют Bootstrap 5.3.8: сетки, отступы, flex, карточки, кнопки, поля, select, radio и checkbox. Для календаря и редакторов включена штатная CSS Grid-сетка Bootstrap; через Utilities API добавлены адаптивные классы `grid-cols-*`. Мобильное меню и переходы управляются Vue; Bootstrap JS не подключён, чтобы два механизма не изменяли один DOM.

Tailwind удалён. Каждый Vue-файл следует порядку `<template>` → `<script setup lang="ts">` → `<style scoped>`; необязательные пустые блоки не добавляются. Порядок проверяет ESLint (`vue/block-order`). Собственные классы используют БЭМ: например, `gallery-filter__option` и `gallery-filter__option--selected`. Стили привязаны к явным классам, а не к вложенным тегам вроде `.contact-body strong`. Каскад состояния допускается только между БЭМ-классами одного блока. Общие цвета, шрифты, настройка Bootstrap, кнопок и общие типографические классы находятся в `src/app/theme.scss`; стили конкретных компонентов — в самих `.vue`. Папки `src/styles` и отдельного слоя стилей форм больше нет.

Общая палитра — тёплый кремовый фон, сливово-розовые и персиковые градиенты. Анимации появления, свечения, переходов и наведения учитывают `prefers-reduced-motion`. Текст можно выделять и копировать на компьютерах и телефонах.

Instagram задаётся в `src/entities/specialist/config/contacts.ts`: `handle` — подпись, `href` — подтверждённый адрес профиля. Сейчас `href: null`, поэтому все кнопки связи открывают `ContactRequestDialog` с примером обращения; из прайса подставляется выбранная процедура. После заполнения `href` они откроют профиль в новой вкладке. Сообщения не отправляются автоматически, запись не создаётся. Телефон и Telegram убраны из публичной связи; телефон клиента в административных карточках остаётся.

Адрес приёма: Беларусь, Солигорск, Кольцевая улица, 5. В контактах встроен официальный виджет Яндекс Карт с отметкой здания, ссылками на карту и построение маршрута. Адрес и ссылки собраны в `src/entities/specialist/config/location.ts`. Приём — по предварительной записи; расписание на публичной странице не заявлено.

Тестовые AI-фото: портрет `public/images/demo/specialist.jpg`, интерьер `studio.jpg`, три примера сравнения `comparison-1.jpg` — `comparison-3.jpg`. Полные промпты и происхождение — `public/images/demo/SOURCES.json`. Это вымышленные изображения, не Ольга, не её кабинет и не результаты процедур; подписи прямо обозначают примеры. Файлы сжаты в JPEG без изменения содержимого; PNG-оригиналы сохранены в каталоге generated_images Codex. Старое изображение `skincare-editorial.png` сохранено, но больше не используется на первом экране.

В галерее три тестовых сравнения и ранее добавленные 40 локальных фото Pexels (источники — `public/images/gallery/SOURCES.md`). Изначально видны две работы, «Посмотреть ещё» добавляет по две; смена категории сбрасывает количество. Пара показывает кадры «До» и «После» одновременно. Нажатие открывает крупный просмотр: на телефоне снимки идут друг под другом, доступны закрытие кнопкой, Escape и нажатием на фон; фокус возвращается к карточке. Реальные загруженные фотографии не обрезаются. Счётчиков фото нет.

Тексты о процедурах — черновики для согласования, без обещаний результата и вымышленных квалификаций. Поля «Когда выбрать», «Что входит», «Перед визитом» редактируются в кабинете вместе с процедурой; они раскрываются в публичном прайсе. Исходные тексты — `src/entities/practice/config/demo.ts`. Блок первого визита — `src/widgets/first-visit/ui/FirstVisit.vue`, интерьер — `src/widgets/studio/ui/StudioSection.vue`. Вдохновение для структуры: [El Studio](https://elstudio.by/), тексты написаны для прототипа самостоятельно.

## Кабинет Ольги

Основной экран — «Мой день»: календарь с отметками записей и выходных, сводка выбранного дня, визиты по времени и поиск клиентов. На телефоне по умолчанию показана неделя; кнопка «Весь месяц» раскрывает полный календарь. Из карточки клиента открывается форма с выбранными клиентом и доступной датой; после сохранения переход возвращает к записи в основном календаре. При смене процедуры доступная выбранная дата сохраняется. Управление прайсом и фотографиями доступно в меню «Сайт».

Мобильное меню расположено абсолютно под закреплённой шапкой и не меняет её высоту, ширину страницы или scroll-палитру. Открытие и закрытие анимированы; Escape и нажатие вне панели закрывают меню. Для reduced motion переходы отключены. Выделение текста выключено, но сохранено в полях ввода и редактируемых областях.

- **Клиенты:** ручное добавление карточек, поиск по имени/телефону, счётчик посещений. Добавление не создаёт аккаунт или визит.
- **Расписание:** ручная запись существующего или нового клиента, выходные и отпуск, отмена и отметка состоявшегося визита.
- **Прайс:** категории и процедуры можно добавлять, редактировать и удалять. Изменения сразу видны в публичном прайсе, фильтрах галереи и форме записи.
- **Фото работ:** два файла «До» / «После» или один снимок/готовый коллаж, до 20 МБ каждый. Проверка декодирования, предпросмотр, подпись с числом визитов и сроком съёмки, привязка к процедуре. Фото хранятся как object URL в памяти вкладки, без отправки на сервер. Обе ссылки освобождаются при удалении работы.
- **Фото сайта:** добавление, замена и удаление главного портрета и фотографии кабинета. Изменения сразу видны на публичной странице, удалённое фото не заменяется автоматически демонстрационным. Пустое место под него убирается из раскладки. Начальные изображения задаются в `src/app/config/site-images.ts`; модель хранит URL и исходные размеры, освобождает object URL при замене, удалении и завершении приложения.

Все фотографии показываются без принудительной обрезки: портрет и одиночные снимки сохраняют свои пропорции, пары используют `object-fit: contain`. На первом экране возвращена декоративная подложка. Начиная с 576 px текст и портрет стоят рядом, на более узком экране — друг под другом с портретом по центру.

Общий загрузчик `src/shared/lib/image-upload` используется в обеих вкладках. Поле `accept="image/*"` позволяет выбирать снимки на телефоне; доступные пункты камеры/галереи определяет браузер ([MDN](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/input/file)). Поддержаны JPEG, PNG, WebP, AVIF и попытка декодирования HEIC/HEIF: если браузер не открывает HEIC, показывается подсказка выбрать JPEG-копию. Серверной конвертации HEIC пока нет. Ориентация снимка учитывается через [`image-orientation: from-image`](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/image-orientation). Загрузка в прототипе локальная, данные остаются до перезагрузки вкладки.

Удаление непустой категории требует переноса процедур. Перед удалением процедуры с фотографиями нужно перенести их на другую процедуру либо удалить через панель фото. История визитов хранит снимок названия, цены и длительности на момент записи и не удаляется вместе с прайсом. Полностью пустой прайс поддерживается.

Счётчик посещений: исходное количество «до сайта» плюс визиты, которые Ольга отметила состоявшимися. Будущие, отменённые и просто подтверждённые записи счётчик не увеличивают. Ошибочную отметку можно снять. Номер визита учитывает предыдущие состоявшиеся посещения и исходное количество.

Расписание: Europe/Minsk, приём 10:00–19:00, начало каждые 30 минут, горизонт 90 дней, воскресенье — исходный выходной. Процедура должна целиком помещаться в рабочее время. Проверка выполняется повторно при подтверждении. Нельзя закрыть период с активными записями; отменённые записи освобождают время.

## Структура FSD

Проект следует [Feature-Sliced Design](https://feature-sliced.design/docs/reference/layers). Слой обозначает ответственность, слайс — конкретный сценарий или предметную область, сегмент внутри слайса — назначение кода (ui, model, lib, config).

```text
src/
  app/                         # запуск, провайдеры, навигация, глобальная тема
  pages/
    home/                      # публичная страница
    cabinet/                   # композиция разделов кабинета
    booking/                   # экран записи и переход к расписанию
    access-preview/            # сохранённый ранний прототип приглашений
    dikidi-preview/            # сохранённый ранний прототип DIKIDI
  widgets/
    site-header/               # шапка и навигация по разделам
    price-list/                # публичный прайс
    work-gallery/              # галерея, категории и загрузка следующих фото
    contacts/                  # Instagram и карта
    studio/                    # знакомство с кабинетом
    first-visit/               # вопросы перед первым визитом
  features/
    book-appointment/          # форма ручной записи клиента
    manage-appointments/       # отмена и отметка посещения
    manage-clients/            # карточки, поиск и прошлые посещения
    manage-catalog/            # категории и процедуры
    manage-schedule/           # выходные и отпуск
    manage-portfolio/          # загрузка и удаление фотографий
    manage-site-images/        # портрет и фото кабинета
    contact-specialist/        # подготовка обращения и диалог связи
  entities/
    practice/                  # связанные данные кабинета и бизнес-правила
    specialist/                # контакты и место приёма Ольги
  shared/
    ui/                        # общие кнопки, стрелки и ссылки
    routing/                   # типизированный контракт навигации
    lib/format/                # форматирование дат и цен
    lib/scroll/                # прерываемая плавная прокрутка
    lib/reveal/                # анимация появления
    lib/image-upload/          # выбор, проверка и предпросмотр фото
  main.ts                      # точка входа Vite
```

**Границы модулей.** Импорты идут вниз: app → pages → widgets → features → entities → shared. Можно пропускать слои. Слайсы одного слоя не импортируют друг друга; исключение — сегменты app и shared. Внешний код использует явный public API модуля — index.ts. Внутри слайса используются прямые относительные импорты, без обращения к собственному index.ts, чтобы не создавать циклы. Относительные пути с расширением .ts работают и в Vite, и в тестах на обычном Node.js.

**Модель практики.** Клиенты, визиты, расписание, каталог и фото составляют один связанный агрегат entities/practice: запись одновременно проверяет клиента, актуальную процедуру и свободное время; удаление категории сохраняет связи фотографий и историю визитов. Состояние каталога находится в model/catalog.ts, общее состояние — в model/practice.ts, чистые правила — в lib/booking.ts, lib/schedule.ts и lib/visits.ts. Это позволяет сохранять целостность операций без циклических импортов между отдельными сущностями. Сценарии и их формы находятся в features, композиция экранов — в pages.

**Состояние и навигация.** app/App.vue создаёт отдельный экземпляр модели и предоставляет его через provide/inject. Модель возвращает обычный объект с ref/computed, поэтому деструктуризация сохраняет реактивность. Экраны, вкладка кабинета, защита переходов и номер сессии формы находятся отдельно в app/model/navigation.ts. shared/routing содержит только контракт и injection helpers, без бизнес-правил и управления историей. Форма записи сообщает события back/show, а страница решает, куда перейти. Панель фото аналогично сообщает openPrice; она не импортирует редактор прайса.

**Публичные API и проверки.** entities/practice/index.ts не импортирует Vue-компоненты. У book-appointment дополнительно есть узкий model.ts для тестирования формы без DOM и загрузчика .vue. Границы проверяет локальное правило ESLint fsd/boundaries из eslint.fsd.js: запрещены зависимости вверх, соседние слайсы, обход public API и импорт собственного barrel-файла. Правило проверяет также реэкспорты и динамические импорты; его поведение покрыто тестами. Внешние интеграционные тесты используют public API; тест app-навигации обращается к её модели напрямую.

**Стили.** src/app/theme.scss содержит настройку Bootstrap, палитру и общую типографику. Стили компонентов остаются в их блоках <style scoped> с БЭМ, порядок блоков — template → script → style. Новых UI-библиотек или зависимостей для FSD не добавлено.

Старые прототипы DIKIDI, приглашений и переключения демо-профилей сохранены, но не подключены к текущему приложению и не входят в его сборку. Совместимость клиентских профилей остаётся в доменных тестах.

## Проверки

```sh
pnpm typecheck
pnpm lint
pnpm test
pnpm build
pnpm check
pnpm format
pnpm format:check
```

Команды доступны и через `npm run <имя>`.

`pnpm lint` запускает Oxlint, затем ESLint; оба завершаются с ошибкой при предупреждениях. `pnpm lint:fix` запускает их автоисправления в том же порядке. Отдельные команды — `pnpm lint:oxlint` и `pnpm lint:eslint`. Полная проверка `pnpm check` включает оба линтера, тесты, проверку типов и сборку.

Oxlint проверяет JS/TS и скрипты Vue-компонентов с настройками из `.oxlintrc.json`. ESLint сохраняет проверки Vue-шаблонов, порядка блоков, обязательного `scoped` и остальные правила, которые не включены в Oxlint. `eslint-plugin-oxlint` читает эту же конфигурацию и отключает только пересекающиеся правила ESLint. При добавлении нового правила сначала определите, какой линтер его выполняет. Подключение следует [официальной схеме совместного запуска](https://oxc.rs/docs/guide/usage/linter/migrate-from-eslint.html#running-oxlint-and-eslint-together).

Prettier отвечает за форматирование. `vue-tsc` проверяет TypeScript и Vue-шаблоны в строгом режиме; Oxlint его не заменяет.

## Переход к рабочему сайту

Для недорогого размещения подходит сборка Vue как статические файлы и небольшой PHP API с MySQL на обычном хостинге. Node.js нужен для сборки, постоянно работающий Node-сервер не требуется. Это проект будущего backend, в текущем прототипе он не реализован.

Постоянная БД нужна для прайса, категорий, карточек клиентов и истории визитов; изображения хранятся в файловом хранилище хостинга. Отсутствие клиентских аккаунтов не отменяет хранение данных кабинета Ольги. Перед реальным запуском необходимы защищённый вход администратора, серверные проверки прав и данных, безопасная загрузка изображений, резервные копии с проверкой восстановления и перенос демо-действий на API. Реальные фото, контакты, тексты и цены согласовать с Ольгой.
